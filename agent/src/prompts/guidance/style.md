Visual/library conventions to follow:
- When you render or import a component defined in another file (a child component, a hook, a utility function), NEVER invent its props/parameters/return type from memory or from the task description alone. Use the exact prop names and types shown for that file in the "Currently generated source files" section below. If the file you need is not shown there yet, keep your usage minimal and consistent with standard React/TypeScript conventions rather than guessing a specific shape.
- Prefer MUI components (Card, CardMedia, CardContent, Grid, Stack, Typography, Button, TextField, IconButton) over raw HTML elements (div, input, button) — MUI's theme only styles its own components.
- If you render a raw <img>/<picture> (for example for responsive breakpoints via <source media="...">), always give the <img> explicit sizing so it fills its container: style={{ width: '100%', height: '100%', objectFit: 'cover' }} (add position: 'absolute', top: 0, left: 0 if the parent uses the padding-bottom aspect-ratio trick). An <img> with no width/height/objectFit renders at an unpredictable size.
- Use MUI's spacing scale (sx={{ p: 2, mb: 3 }}, theme units) instead of hardcoded pixel margins/padding.
- Use MUI's Grid or Stack (or CSS Grid via sx={{ display: 'grid', gridTemplateColumns: ... }}) for responsive card layouts instead of manual flex-wrap arithmetic.
- Give Card/Paper elements an elevation (elevation={1..3}) or a defined border — do not leave interactive surfaces with no visual depth cue.
- Each component's responsibility must match its name and task description exactly — a component whose job is to render an image (e.g. "ResponsiveImage", "CardMedia wrapper") must render ONLY the image, never a duplicate copy of a title/label/price that a parent or sibling component already renders. Before adding any Typography/text to a component, check the "Relevant already-generated files" and "Currently generated source files" sections below for whether a parent or sibling already displays that same data — never render the same entity's title or attributes twice across nested components.
- MUI's Typography renders a <p> tag by default (even for variant="body1"/"body2"/"h6" etc.). Never nest a Box, div, or other block-level element inside a Typography — this produces invalid HTML (a <div> inside a <p>) and unpredictable/duplicated DOM output. If you need an icon or color swatch next to text, put the swatch and the text as sibling children of a Box/Stack, not one nested inside the other's Typography; or set component="div" on the Typography if it must contain block-level children.
- Never swallow an error in a try/catch without at least logging it (console.error(err) or similar) before converting it to a generic UI message. A silently-caught error hides its real cause from anyone (including a future automated fix pass) trying to diagnose a failure later — always leave a trace of the actual underlying error, not just a friendly message.
